# 桌宠项目架构重构计划

## 问题分析

用户提出的疑问：
1. 项目目标是 Windows 桌面应用，为什么用 React？
2. 为什么要分前后端？桌面应用应该是服务+应用一体

### 当前架构问题

当前文档描述的是"前后端分离"架构：
- 前端：React + Vite
- 后端：Node.js + Express
- 数据库：MySQL（远程）+ SQLite（本地）

这种架构适合 Web 应用，但对于桌面应用来说过于复杂。

### 正确的桌面应用架构

桌面应用应该是**单体架构**：
- 一个可执行文件包含所有功能
- 本地数据存储为主
- 可选的远程数据同步服务

## 技术方案对比

### 方案一：Electron（当前方案）

**架构**：
```
Electron 应用
├── 主进程（Node.js）- 处理系统交互、文件操作、数据库
├── 渲染进程（Web 技术）- UI 界面
└── 打包成一个可执行文件
```

**优点**：
- 成熟稳定，生态丰富
- 跨平台（Windows、Mac、Linux）
- 可以使用 Web 技术开发 UI
- 打包后是单个可执行文件

**缺点**：
- 体积较大（包含 Chromium）
- 内存占用较高

### 方案二：Tauri（推荐）

**架构**：
```
Tauri 应用
├── Rust 后端 - 处理系统交互、文件操作、数据库
├── Web 前端 - UI 界面（可用 React/Vue/Svelte 等）
└── 打包成一个可执行文件
```

**优点**：
- 体积小（使用系统 WebView）
- 性能好（Rust 后端）
- 安全性高
- 内存占用低

**缺点**：
- 相对较新，生态不如 Electron
- 需要 Rust 开发经验

### 方案三：纯原生（C++/C#）

**优点**：
- 性能最好
- 体积最小

**缺点**：
- 开发效率低
- 跨平台困难
- 需要原生开发经验

## 确认方案

**用户选择：Electron 单体架构**

考虑到项目需求（跨平台、AI 集成、屏幕分析），采用 **Electron 单体架构**：

### 架构设计

```
桌宠应用（单个可执行文件）
├── 主进程（Main Process）
│   ├── 系统集成
│   │   ├── 窗口管理
│   │   ├── 托盘图标
│   │   ├── 开机自启
│   │   └── 系统通知
│   ├── 硬件控制
│   │   ├── 键盘鼠标控制
│   │   ├── 屏幕捕获
│   │   ├── 音频处理
│   │   └── 摄像头访问
│   ├── 数据存储
│   │   ├── SQLite 数据库
│   │   ├── 文件存储
│   │   └── 配置管理
│   └── 网络服务
│       ├── AI API 调用
│       ├── 数据同步（可选）
│       └── 模型下载
├── 渲染进程（Renderer Process）
│   ├── UI 界面
│   │   ├── 桌宠渲染
│   │   ├── 聊天界面
│   │   ├── 换装界面
│   │   └── 设置界面
│   ├── 动画系统
│   └── 交互逻辑
└── 资源文件
    ├── 人物模型
    ├── 服装资源
    ├── 音效资源
    └── 配置文件
```

### 关键变化

1. **移除"前后端分离"概念**
   - 主进程 = 后端逻辑
   - 渲染进程 = 前端 UI
   - 两者通过 IPC 通信，打包成一个可执行文件

2. **数据存储调整**
   - 主要使用本地 SQLite
   - 远程 MySQL 作为可选的"数据同步服务"
   - 用户自行配置服务器地址

3. **项目结构简化**
   ```
   desktop-pet/
   ├── src/
   │   ├── main/           # 主进程代码
   │   │   ├── index.ts    # 入口
   │   │   ├── database/   # 数据库
   │   │   ├── hardware/   # 硬件控制
   │   │   ├── screen/     # 屏幕分析
   │   │   └── ai/         # AI 服务
   │   ├── renderer/       # 渲染进程代码
   │   │   ├── index.html
   │   │   ├── App.tsx     # React 应用
   │   │   ├── components/
   │   │   └── pages/
   │   └── shared/         # 共享代码
   │       ├── types/
   │       └── utils/
   ├── resources/          # 资源文件
   ├── electron-builder.yml
   └── package.json
   ```
